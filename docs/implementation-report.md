## Дополнительные исправления

- Отзыв доступа удаляет все ранее выданные сессии пользователя. Реактивация не восстанавливает старую cookie.
- Параллельные операции с доступом сериализуются; права исполнителя повторно проверяются внутри транзакции. Неизменяемый активный владелец сохраняет минимум одного super_admin.
- Изменяющие запросы без Origin или с чужим Origin отклоняются, включая вход, выход, checkout и upload. API не доверяет произвольному X-Forwarded-For; размеры тела и пачки запросов ограничены.
- Перед передачей изображения native-декодеру проверяется сигнатура разрешённого формата. Метаданные удаляются, размер ограничивается. Production-каталог загрузок обязан быть абсолютным и находиться вне dist.
- Исправлены пути production SPA fallback; проверены вложенный маршрут панели и загрузка JS-ресурсов.
- URL контактов и изображений валидируются. Нельзя удалить коллекцию с товарами; нельзя записать товар в несуществующую коллекцию.
- Уведомление о новых заказах в навигации и список заказов обновляются каждые 15 секунд.
- Формы товаров и коллекций сохраняют введённые данные при ошибке сервера и закрываются после успешной записи.
- Карточки выбора коллекции оформлены кнопками. В формах товаров, коллекций и контента добавлена кнопка загрузки фото на существующем Button; кнопка выхода переведена на тот же компонент. Состояния focus/active/disabled и переходы согласованы; публичная ссылка на панель удалена. Остальные навигационные ссылки сохранены.
- Удалены неиспользуемые компоненты прежней панели в витрине, шаблонные UI-компоненты, старые помощники и браузерный сборщик логов. Упоминания удалённой интеграции в историческом аудите заменены нейтральным обозначением.
- Дополнительный npm audit выявил уязвимые версии обработчика изображений и Node-адаптера. Обновлены до sharp 0.35.5 и @hono/node-server 2.1.6. Основание: [уведомление sharp](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w), [уведомление Node-адаптера](https://github.com/honojs/node-server/security/advisories/GHSA-rmxm-3fg6-px4f).

## Ограничения и настройка сервера

- Реальный Telegram Login с вашим ботом и HTTPS-доменом не выполнялся: токен и серверный домен не предоставлены. В тестах используются подписанные тестовые пакеты. Настройте legacy Login Widget через BotFather, переменные TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_NAME и SUPER_ADMIN_TELEGRAM_ID.
- MySQL локально не запускался: доступный сервер/контейнер отсутствует. В GitHub Actions для коммита `50d5b86` успешно прошли чистая установка npm ci, обе миграции MySQL 8.4, `npm run test:mysql`, 41 тест, сборки и production-проверка. Шаг Gitleaks завершился ошибкой построения диапазона с родителем первого коммита, до проверки содержимого. Исправленный шаг запускает закреплённую версию CLI с `--log-opts="--all"`, проверяет всю доступную историю, включая первый коммит, и сохраняет SARIF-отчёт с замаскированными секретами.
- На существующей БД CREATE IF NOT EXISTS не исправляет несовместимые старые столбцы и не добавляет FK/индексы к старым таблицам. Перед обновлением такой БД нужна резервная копия и отдельная проверенная ALTER-миграция на копии. Для этого нового репозитория миграции проверяются на чистой БД.
- Сборка предупреждает о размере JS-пакета панели около 928 КБ до gzip. Это предупреждение производительности, сборку оно не блокирует.
- Внешняя рассылка уведомлений и оплата не реализованы: новый заказ виден в панели и её счётчике; клиент получает номер и сумму. Доставка и наличие подтверждаются вручную.
- Перед запуском задайте NODE_ENV=production, APP_SECRET, PUBLIC_ORIGIN (HTTPS), параметры БД, абсолютный постоянный UPLOAD_DIR; настройте TLS reverse proxy, лимиты по реальному IP на прокси, права каталога, резервное копирование и сроки хранения журналов/контактов. Замените демонстрационные тексты и контакты seed.
- Production-развёртывание и создание веток не выполнялись. После отдельного разрешения пользователя коммиты отправлены в origin/main.
