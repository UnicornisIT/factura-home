# Установка Factura Shop на VPS

Нужен сервер с systemd под Ubuntu 22.04+ или Debian 12+, доступ к пакетам ОС, NodeSource, npm, GitHub и Telegram, публичный HTTPS-домен и бот, созданный в BotFather. Используйте доверенную копию репозитория, содержащую этот мастер, и версию Factura с командой `db:bootstrap-admins`.

```bash
sudo bash deployment/setup.sh
```

## Что спрашивает мастер

1. Показывает версию ОС, архитектуру, свободное место и установленные компоненты. Определяет существующую установку по `app/.env` и конфигурации сервиса.
2. Предлагает репозиторий `UnicornisIT/factura-home` и последний стабильный опубликованный релиз GitHub. Можно указать другой тег. Для приватного HTTPS-доступа укажите fine-grained PAT с правом Contents: read. В режиме SSH укажите путь к deploy key, а для GitHub API приватного репозитория также укажите PAT. Для публичного репозитория PAT можно оставить пустым.
3. Предлагает SQLite с постоянным файлом (по умолчанию `/var/lib/factura/factura.db`) или MySQL. Для MySQL можно установить локальный сервер, использовать имеющийся локальный сервер через Unix-сокет или подключиться к заранее подготовленной внешней базе. Ubuntu устанавливает пакет `mysql-server`, Debian запускает MySQL 8.4 в Docker с постоянным томом и портом на localhost. Для локального сервера мастер создаёт БД и выделенного пользователя. Для внешнего нужны хост, порт, имя базы, пользователь и пароль. Пользователю нужны права на чтение и запись, создание, изменение и удаление таблиц, создание индексов и внешних ключей. Мастер проверяет эти операции на временных таблицах.
4. Запрашивает публичный HTTPS-адрес и способ завершения TLS. При необходимости готовит Nginx с одним upstream для витрины, панели, API и изображений. Приложение слушает `127.0.0.1`, порт по умолчанию `3000`.
5. Запрашивает username и токен Telegram-бота. Проверяет их соответствие через `getMe`. Привяжите публичный домен к боту командой `/setdomain` в BotFather, чтобы Telegram Login Widget принимал вход с этого домена.
6. Запрашивает Telegram ID владельца (`super_admin`), количество обычных администраторов и их Telegram ID. Нужны числовые ID пользователей от 1 до 9007199254740991. Введите `0`, если обычных администраторов пока нет. Мастер показывает список перед подтверждением.
7. Предлагает системного пользователя `factura`, корень приложения `/opt/factura`, данные `/var/lib/factura`, изображения `/var/lib/factura/uploads`, копии `/var/backups/factura` и журналы `/var/log/factura`. Каталоги и порт можно задать при установке. `APP_SECRET` генерируется автоматически.
8. Предлагает включить обновление через панель и отдельно добавить демонстрационные товары и коллекции. По умолчанию обе опции выключены при новой установке.

Перед записью мастер показывает сводку с выбранными параметрами и пакетами. Пароли и токены вводятся скрыто. Конфигурация приложения записывается атомарно в `app/.env` с правами `0640`, владелец `root`, группа сервиса.

## HTTPS

| Режим | Что нужно подготовить |
| --- | --- |
| `letsencrypt` | DNS домена должен указывать на VPS. Откройте входящие TCP 80 и 443, укажите email и подтвердите условия Let's Encrypt. Мастер использует Certbot с webroot, настраивает перенаправление с HTTP на HTTPS и перезагрузку Nginx после продления. |
| `certificate` | Укажите абсолютные пути к PEM-файлу сертификата с цепочкой и приватному ключу. Обновление этих файлов и перезагрузку Nginx обеспечивает ваш процесс выдачи сертификатов. |
| `external` | Подготовьте HTTPS-прокси на этом сервере или туннель к `127.0.0.1:3000` (либо к выбранному порту). Передавайте `Host`, `Origin` и `Cookie`, ограничьте тело до 6 МБ и сохраните работу Telegram popup. Мастер проверяет итоговый публичный URL через TLS. |
| `existing` | При повторной настройке используйте действующую конфигурацию домена и порта. |

Встроенный Nginx использует отдельный файл для Factura и проверяет конфигурацию перед перезагрузкой. Если домен уже настроен вручную, выберите внешний или существующий прокси.

Мастер включает `TRUSTED_PROXY_IP=127.0.0.1` для управляемого Nginx. Для существующей установки, обновлённой без мастера, укажите `TRUSTED_PROXY_IP=127.0.0.1` в `app/.env`, если Nginx подключается к приложению по loopback и устанавливает `proxy_set_header X-Real-IP $remote_addr;`. Для другого прокси укажите его фактический IP при подключении к приложению. Прокси должен перезаписывать `X-Real-IP` и ограничивать доступ к backend. Без этой настройки приложение использует IP соединения. Настройка вступает в силу после перезапуска сервиса.

## Доступ администраторов

Миграции создают защищённого владельца по `SUPER_ADMIN_TELEGRAM_ID`. Мастер проверяет его роль и после проверки сервиса вызывает `npm run db:bootstrap-admins -- ID ...` из каталога `app`. Команда добавляет новые ID с ролью `admin` в одной транзакции на SQLite или MySQL. В записи и журнале аудита указывается владелец. Список ID хранится в БД. Уже выданные роли и отозванные доступы сохраняются при повторном запуске. Для изменения существующим пользователям ролей и доступа используйте раздел «Доступ» админ-панели.

## Повторная настройка и восстановление

Запустите ту же команду и подтвердите каталог действующей установки. Мастер использует текущий релиз, системного пользователя, каталоги, базу и ID владельца. Можно обновить пароль и пользователя той же БД, домен, HTTPS, порт, токены GitHub и Telegram, настройки обновления и добавить новые ID. Секрет сессий сохраняется по умолчанию. Явная замена `APP_SECRET` потребует повторного входа.

Перед изменением действующей установки мастер сохраняет БД, изображения и конфигурацию в отдельном каталоге `setup-…` внутри каталога резервных копий. При сбое после записи конфигурации он восстанавливает файлы сервиса, приложения и Nginx и предыдущее состояние запуска. Изменения БД после миграций или seed восстанавливаются из резервной копии вручную. Если первая установка прервалась, исправьте показанную ошибку и повторите запуск с тем же каталогом и тегом. Пакеты, checkout и постоянные данные сохраняются.

Для диагностики используйте `journalctl -u factura -n 100`, `systemctl status factura` и, при локальном Nginx, `nginx -t`. Если требуется восстановить БД, сначала остановите сервис и сохраните текущее состояние отдельно. SQLite-копия хранится как `shop.db`, дамп MySQL — как `mysql.sql`, изображения — как `uploads.tar.gz`. Восстановите их в ту же конфигурацию либо во временный каталог для проверки и затем запустите сервис.

После прерывания миграции MySQL можно повторить `npm run db:migrate` из каталога `app`. Команда сверяет уже добавленные колонки и уникальный индекс с ожидаемой схемой, затем завершает оставшиеся операции и записывает checksum. При сообщении о несовместимой или частично определённой схеме сохраните дамп и проверьте определения объектов перед следующим запуском.

## Проверки завершения и обновления

Мастер проверяет состояние systemd, локальный и публичный API, версию релиза, роль владельца и отказ во входе для отсутствующего в списке Telegram ID. Для обычных администраторов проверяется запись с ролью `admin` и ID владельца. После установки проверьте вход с реальным аккаунтом владельца через Telegram.

При включении обновлений мастер проверяет GitHub API и Git, устанавливает root-скрипт обновления и проверенную через `visudo` запись для системного пользователя. Владелец может запустить обновление до последнего опубликованного релиза на странице «Обновление сервера». При обновлении используется тот же каталог резервных копий. Подробнее см. [описание механизма обновления](../README.md#релизы-и-обновление-сервера).
