# Уведомления об обновлениях Factura Home

Колокольчик в шапке админ-панели показывает новые релизы, запуск и результат установки. У каждого администратора свой счётчик непрочитанных. Можно отметить одно уведомление или прочитать все сразу. Обычный администратор видит общие сведения и ссылку на GitHub. В разделе «Обновление сервера» `super_admin` может запустить установку и посмотреть историю попыток, версии, инициатора и результат отката.

## Подписка в Telegram

1. Откройте колокольчик и нажмите «Настроить Telegram».
2. Нажмите «Открыть бота», разблокируйте его при необходимости и отправьте `/start`.
3. Нажмите «Включить». Бот пришлёт проверочное сообщение. Связь можно проверить и отдельной кнопкой.

Настройки уведомлений об обновлениях и заказах независимы. При отключении подписки или отозванном доступе ожидающие отправки отменяются. Сообщение, уже принятое Telegram, остаётся в чате.

## Развёртывание и работа

- Примените миграцию `009_update_notifications` штатной командой `npm run db:migrate` из каталога `app`. Миграции включены в штатный цикл установки и поддерживают SQLite и MySQL.
- Для новых установок и ручного обслуживания используйте актуальный системный скрипт обновления. При необходимости [переустановите механизм обновления](updater-reinstall.md). Старый скрипт оставляет только последний статус. При импорте такого статуса приложение сохраняет доступные сведения и показывает неизвестного инициатора, если подтвердить его невозможно.
- Рабочий сервер проверяет последний стабильный релиз GitHub при старте и затем раз в 30 минут. Он сравнивает его с версией запущенной сборки. При первом запуске последний совместимый релиз новее установленного появляется в панели. Telegram получает только релизы с датой публикации позже сохранённого времени запуска монитора. Установка запускается вручную командой или из раздела `super_admin`.
- Скрипт атомарно обновляет файл `SERVER_UPDATE_STATUS_PATH` и отдельный файл `<status>.operation-<id>.json` на операцию. Итог «Успешно» записывается после проверки работоспособности. При откате итог попытки остаётся «Ошибка», отдельно сохраняется результат восстановления. Приложение считывает журнал при старте и каждые пять секунд, сохраняет его в БД и убирает завершённые снимки спустя сутки. Каталог файлов статуса должен быть доступен сервису для чтения и удаления обработанных снимков.
- Если операция перестала обновлять статус, через два часа без продвижения история покажет «Итог не подтверждён». Для старого формата статуса действует 30-минутное окно. Когда скрипт запишет окончательный результат, приложение подхватит его. История попыток хранится в БД. В колокольчике видны события за 180 дней. Старые отметки прочтения, задачи доставки и описания удаляются, ключи событий сохраняются для дедупликации.
- Краткое описание релиза формируется из структуры Markdown. Полный текст в панели поддерживает GitHub Flavored Markdown. Бот отправляет сокращённое описание в безопасном HTML Telegram, а при отказе принять форматированный текст повторяет отправку обычным текстом.
- При полной недоступности приложения доставка Telegram не гарантируется. После восстановления приложение обработает сохранённые события. Из журнала установок в Telegram ставятся операции за последние семь дней. Если Telegram принял сообщение, а ответ потерялся, при повторной отправке возможен дубль. Сопоставить сообщения можно по версии релиза или идентификатору операции.
