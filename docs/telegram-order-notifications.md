# Telegram-уведомления о заказах

Установите обновление штатным способом: сначала применяются миграции (`npm run db:migrate` из каталога `app`), затем запускается новая версия сервера. Используются действующие `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_NAME` и `PUBLIC_ORIGIN`. Новые таблицы не меняют существующие заказы. Старые заказы не рассылаются.

Каждый администратор, включая Super Admin, открывает **Заказы → Telegram-уведомления → Открыть бота**, нажимает `/start` в Telegram и включает уведомления. При включении бот отправляет проверочное сообщение. Дополнительную проверку можно запустить в том же блоке. Подписка привязана к Telegram-аккаунту из сессии админки. При деактивации подписка удаляется; после восстановления доступа её нужно включить снова.

Заказ и задачи на каждого подписанного администратора появляются в БД одновременно. Сервер отправляет их отдельным обработчиком. Захват задачи с ограниченным сроком и уникальным идентификатором защищает от параллельной обработки несколькими экземплярами. Перед отправкой обработчик проверяет доступ и подписку снова. Отключение не может отозвать уже начатый запрос к Telegram.

При временном сбое доставка повторяется с увеличивающимся интервалом, при HTTP 429 учитывается время ожидания из ответа Telegram. После шести попыток или постоянной ошибки задача становится конечной. Если Telegram принял сообщение, но процесс не успел сохранить результат либо ответ потерялся, после восстановления возможен дубль с тем же номером заказа: Bot API не принимает ключ идемпотентности для `sendMessage`. При длинном заказе названия и комментарий могут быть сокращены; полные данные остаются в админке.
