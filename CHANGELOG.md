## [0.2.4] - 2026-11-10

### Исправлено

- Загрузка фотографий больше не может зависнуть навсегда: запрос `/api/upload` прерывается на клиенте по тайм-ауту (60 с), обработка изображения на сервере ограничена по времени (15 с), все этапы (разбор тела, Sharp, запись файла, аудит) отвечают явными кодами 400/401/403/413/500 с безопасными сообщениями.
- Кнопка «Загрузить фото» гарантированно выходит из состояния «Загрузка…» при ошибке, отмене, тайм-ауте и размонтировании компонента; повторная загрузка из одного компонента блокируется; ответ сервера проверяется на структуру `{ url }`.
- Сбой записи audit-журнала после сохранения файла больше не приводит к потере URL: клиент получает готовый адрес изображения, ошибка журнала фиксируется в логе.
- Кнопки «Сохранить»/«Создать» в формах коллекций и товаров блокируются, пока идёт загрузка фото, — URL обложки не теряется из-за преждевременного сохранения.

### Добавлено

- Интеграционные тесты загрузки через настоящий HTTP-стек (@hono/node-server): multipart с Content-Length и chunked, 401/403/413, повреждённое изображение, ошибка записи файла, зависание Sharp, сбой аудита, сохранение URL в БД и доступность файла по `GET /uploads/:name`.
- Тесты компонента `ImageUpload` (vitest + testing-library в админ-панели): успех, тайм-аут, сетевая ошибка, некорректный ответ, повтор после ошибки, обновление поля ссылки на обложку.
- Журналирование этапов загрузки на сервере (этап, категория ошибки, размер, длительность) без путей, секретов и содержимого файлов.

## [0.2.3] - 2026-11-10

### Добавлено

- Обложка главного экрана: явный выбор компоновки — «текст слева и фото в арке» (split) или «по центру» (center), вертикальный фокус главного фото (верх/центр/низ); пока фото не загружено, в арке показывается декоративная заглушка, а форма предупреждает об этом.
- Блок «Контакты»: фирменные иконки мессенджеров (Telegram, WhatsApp, ВКонтакте, email) на кнопках связей.

### Изменено

- Стартовые блоки нового магазина наследуют значения из библиотеки блоков: обложка сразу создаётся с компоновкой split и списком преимуществ.
- Форма блока «Каталог»: пояснение про поведение колонок (две категории — во всю ширину, от пяти — адаптивная сетка).
- Стили лендинга обновлены под новую компоновку обложки.
- Страница «Доступ»: подсказка про определение Telegram ID (@userinfobot) перенесена под форму добавления администратора.

## [0.2.2] - 2026-11-10

### Исправлено

- Учётные данные GitHub разделены: API и git-доступ используют только `GITHUB_TOKEN`; `SERVER_UPDATE_TOKEN` больше не передаётся в GitHub API (причина 401 на сервере). Публичный репозиторий работает без токена, коды 401/403/404/429/5xx отображаются в панели с понятными сообщениями.
- Скрипт обновления определяет корень установки сам (`/opt/factura/current` или `/opt/factura`, нестандартная раскладка — через root-конфиг `/etc/factura/update.env`); ошибки путей и конфигурации пишутся в статус-файл и журнал до остальных шагов — панель всегда видит реальную причину сбоя.
- Git-операции выполняются от имени владельца репозитория: устранён `detected dubious ownership`, SSH deploy key доступен без предоставления root-доступа к пользовательским каталогам.
- Незакоммиченные изменения рабочего дерева блокируют обновление понятной ошибкой до каких-либо изменений; файлы не уничтожаются (без безусловных `reset --hard`/`clean -fd`).
- Обновление, запущенное из панели, переносит себя в transient unit systemd (`systemd-run`): перезапуск `factura.service` больше не может прервать обновление и healthcheck; `KillMode=process` сохранён как второй рубеж.
- Токен не передаётся в аргументах процессов `curl` и `git` (временный config-файл 600 и credential-файл 600), не попадает в журнал и статус.
- Проверяются источник обновления (`origin` соответствует `SERVER_UPDATE_REPOSITORY`), доступ к GitHub (`ls-remote`) до изменений и формат имени релиза перед checkout.
- Шаблон systemd-юнита проверяется `systemd-analyze verify`, а sudoers — `visudo -c` перед заменой; при сбое файлы не подменяются.
- Статус-файл пишется атомарно, содержит этап операции; непредвиденное завершение скрипта (сигнал, set -e) больше не оставляет вечный `running`.

### Безопасность

- `ReadWritePaths` сервиса больше не включает `/usr/local/sbin` и `/etc/systemd/system`: процесс под пользователем `factura` не может перезаписать привилегированный скрипт обновления или юниты. Root-файлы переустанавливает transient unit вне mount namespace сервиса.
- Скрипт обновления, юнит и sudoers устанавливаются из архива проверенного тега, скачанного root'ом с GitHub, а не из рабочего дерева приложения (дерево принадлежит пользователю сервиса и доверенным источником не является).
- `app/.env` разбирается как данные (`KEY=VALUE`) и не исполняется как shell от root.
- Из sudoers-записи убран `env_keep FACTURA_APP_DIR`: непривилегированный вызывающий не может подсунуть скрипту произвольный каталог установки.

### Добавлено

- Панель «Обновление сервера»: прогресс по 12 этапам, восстановление прогресса и результата после перезагрузки страницы, повторные опросы API во время перезапуска сервиса, итоговый баннер только после подтверждения результата сервером.
- `deployment/setup.sh`: доступ к Git через SSH deploy key (хранение в `/var/lib/factura/keys`, `core.sshCommand` в конфигурации репозитория); включение обновления из панели доступно и публичным репозиториям без токена.
- `deployment/factura-update.sh` переустанавливает из архива нового тега не только себя и юнит, но и sudoers-запись (с проверкой и резервными копиями).
- Интеграционные тесты скрипта обновления (bash, Linux CI): успешное обновление с этапами, 401/500 GitHub API, недопустимое имя релиза, неверный путь установки, локальные изменения, недостоверный и недоступный origin, сбой загрузки архива релиза, сбой `npm ci` и healthcheck с откатом, параллельный запуск, отсутствие токена в журнале и статусе; статические проверки границ привилегий (sudoers без `env_keep`, `ReadWritePaths`, `.env` без исполнения).

### Изменено

- `SERVER_UPDATE_TOKEN` удалён из конфигурации — используйте `GITHUB_TOKEN`; одноразовая процедура перехода действующего сервера описана в `docs/server-update-migration.md`.

## [0.2.1] - 2026-11-10

### Исправлено

- Обновление из админ-панели: `KillMode=process` в шаблоне `factura.service` — `systemctl restart` внутри скрипта обновления больше не убивает сам скрипт до записи статуса и healthcheck.
- `ReadWritePaths` юнита теперь включает каталоги скрипта обновления (`/usr/local/sbin`) и юнитов (`/etc/systemd/system`): без них переустановка deployment-файлов падала с EROFS под `ProtectSystem=full` и уходила в откат.
- Статус-файл обновления (`update-status.json`) принадлежит пользователю сервиса (`User=` из юнита), а не владельцу каталога приложения — панель видит статус даже при смешанных правах.
- Sudoers-запись пробрасывает `FACTURA_APP_DIR` в скрипт обновления для серверов с нестандартной раскладкой (не `/opt/factura/current`).
- Шаблон юнита поддерживает опциональный `EnvironmentFile=-/etc/factura/factura.env`.

## [0.2.0] - 2026-11-09

### Добавлено

- Редизайн витрины по эскизам «тёплой мастерской»: кремовая палитра, бордовые и оливковые акценты, арочные фотографии, декоративные ветви, крупные заголовки с засечками. Сайт остался одностраничным лендингом на `/`.
- Дизайн-токены сайта: раздел админки «Дизайн сайта» (палитра из 17 цветов, шрифты из безопасного набора, скругления, плотность компоновки, прилипающая шапка, арочные фото и декор). Токены хранятся в БД и применяются через CSS-переменные.
- Страница «Предпросмотр» в админке: витрина в iframe с режимами desktop/tablet/mobile.
- Расширены блоки конструктора: обложка (надпись над заголовком, главное фото в арке с выбором стороны, преимущества с иконками), «О мастерской» (подпись фото, цитата, преимущества), «Каталог» (описание, число колонок), «Товары» (заголовок секции, фильтр «Все категории»), «Доставка» (фото, информационные карточки с иконками).
- Новый singleton-блок «Контакты»: заголовок, текст, фото и кнопки Telegram/WhatsApp/ВКонтакте/email из настроек контактов; пустые ссылки не показываются.
- Настройки шапки и подвала в админке: логотип, видимость названия, ручное меню (подписи, порядок, видимость, якоря секций), дополнительный текст футера, ссылка ВКонтакте.
- Описание коллекций: показывается на карточке категории и под заголовком фильтра товаров.
- Миграция `004_design_and_content` (SQLite и MySQL): новые колонки `siteContent` и `collections.description`.

### Изменено

- Все секции лендинга стилизованы централизованными токенами; цвета по умолчанию соответствуют новой палитре.
- Старые сохранённые блоки и данные остаются валидными: новые поля необязательны, повреждённые JSON настроек заменяются значениями по умолчанию.
- `X-Frame-Options: DENY` заменён на `SAMEORIGIN` в production (в dev — CSP `frame-ancestors`) для предпросмотра витрины из админки.

## [0.1.1] - 2026-11-09

### Изменено

- Технические идентификаторы `glina` заменены на `factura`: пакеты `factura-shop` и `factura-shop-admin`, cookie `factura_admin_sid`, сервис `factura.service`, скрипты `deployment/factura-update.sh` и `deployment/setup.sh`, пути `/opt/factura`, `/var/lib/factura`, `/var/log/factura`, `/var/backups/factura`, база и пользователь MySQL, тестовая БД CI. Бренд «Глиняная мастерская» в интерфейсе сохранён.
- Скрипт обновления автоматически переустанавливает себя и systemd-юнит из нового тега (атомарно, с резервной копией); при откате предыдущие версии файлов деплоя восстанавливаются.

### Добавлено
